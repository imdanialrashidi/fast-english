# Project execution policy

Follow `AGENTS.md` as the repository map and load detail only when the current decision needs it.

Classify before ceremony. For non-trivial work, align a compact observable acceptance contract, implement one coherent slice with exactly one active writer, run the cheapest faithful evidence first, inspect the final diff, and report criterion → evidence. Use OMP's bundled agents and native commands directly; load a project skill only when its narrow contract matches the work: browser-QA, test-design, verification-routing, accessibility-audit, web-performance, technical-seo or rtl-i18n. Run project-context readiness before product work; do not infer product facts from empty templates. Never claim an unexecuted check, unseen rendering, or unsupported external fact passed.

Routine reversible implementation includes automatic PR handoff under `docs/GIT_POLICY.md`: use the reviewed `scripts/ai-pr.mjs` helper on the persistent `ai-changes` branch after scoped verification. No per-task branches, main writes, or automatic merge. Read-only/local-only work and evals never publish. Other external/Git actions remain owner-controlled.

When the same approach fails twice without new evidence, stop repeating it, preserve the failure, form competing hypotheses, and gather the cheapest discriminating observation. Finish all unblocked work before requesting a missing prerequisite.
