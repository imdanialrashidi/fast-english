# Fast English — Architecture Contract

Source: scope §2 (stack), §5 (roles), §8 (access/time), §9 (content), §10–11 (payment/subscription), §13 (player/progress), §14 (data model), §15 (state ownership), §16 (file delivery/security), §18 (PWA/TWA), §19 (deploy/ops). Section numbers refer to the scope.

## Current system

- Runtime: PHP 8.4 (supported patch), Laravel 13.x, Nginx + PHP-FPM, PostgreSQL (supported), Vite asset build, Node for build only (§2).
- Learner/public UI: Inertia 3 + React 19 + TypeScript + Tailwind CSS 4 + shadcn/ui, single permanent light theme (see `docs/adr/0002-inertia-react-learner-frontend.md` for the binding decision) (§2).
- Staff: one Filament 5.x panel (`/admin`) with its internal Livewire isolated; learner Filament assets never loaded in learner layout (§2).
- Auth: Fortify with Inertia pages (login, register, reset, standard security) (§2). Owner request 2026-11-12 adds an additive phone-code path: `users.phone` nullable/unique, six-digit codes hashed in `phone_verification_codes`, and one `App\Support\Sms\SmsSender` boundary (MelliPayamak in production; log outside production). Email + password remains for existing accounts and staff. Owner request 2026-11-13 narrows SMS to exactly two approved MelliPayamak patterns — the login/verification code and the subscription-activation confirmation — so there is no free-text path. Every attempt is audited in `sms_messages`; `sms:check-deliveries` only reads delivery reports and never resends. Codes/phone numbers are never logged in production or passed to Inertia payloads; the activation notice is queued after commit and cannot change money/access state.
- Topology: one Laravel app, one database, one origin. No subdomains, no separate auth client, no parallel REST API, no Node API server (§15, §6).
- Resolved versions pinned in `composer.lock` + `package-lock.json` (+ PHP/Node pins) at S0; majors never auto-bumped per session (§2). No Redis/Octane/WebSocket/standalone search/monorepo/public API/Docker required by this scope (§2).

## State ownership — one owner per piece of state (scope §15)

| State | Owner | Rule |
|---|---|---|
| Data, role, publication, access, money | PostgreSQL / Laravel (server) | Client never authoritative |
| Browse level, category, query, page | URL (`?level=`, filters, pagination) | Back/share/refresh compatible; silent default change forbidden |
| `preferred_level` | `users` row | Only explicit settings change or placement-result accept |
| `recommended_level` | Latest completed placement attempt | Browsing a level never changes it |
| Forms + validation | Inertia / Laravel (server) | Server is validation reference |
| `currentTime`, speed, play state | One transport (`resources/js/lib/audio.ts`) behind the persistent learner adapter (`resources/js/lib/player.tsx` + `resources/js/components/AudioPlayer.tsx`) and the local public adapters | No round-trip for instant controls; never bind `timeupdate` to server |
| Confirmed progress | DB `lesson_progress` scoped to (user, lesson) | Browser only requests saves |
| Sentence cues | Removed 2026-10-21 (columns `lessons.audio_cues`/`audio_cues_revision` dropped) | Retired by owner direction: no cue props, no highlight/seek; plain paragraphs only |
| Vocabulary state | DB `vocabulary_words` scoped to (user) | Client only requests save/review/remove; ownership enforced server-side |
| Flashcard state | DB `user_flashcards` + `flashcard_reviews` scoped to (user, card) | Client posts a rating and a `client_review_id`; the server owns the schedule and rejects/replays duplicates |
| Daily goal | `users.daily_goal_minutes` (5/10/15) | Explicit settings change only; never writes `preferred_level` |
| Guest non-sensitive preference | Limited `localStorage` | No tokens, receipts, lesson bodies, answer keys |
| Agent content access | `mcp_tokens` + MCP route middleware | Bearer token hashed at rest, staff-only, abilities read/write/publish; never a session cookie |
| Theme | Fixed light in v1 | Dark/system needs its own scope |

Code homes (§15): `routes/web.php` (pages + essential media/controller routes) · `routes/ai.php` (staff MCP content server + staged upload route; outside the web/session/CSRF stack) · `app/Models` · `app/Policies` · `app/Http/Controllers` (Inertia responses + protected files + essential HTTP) · `app/Http/Requests` · `app/Actions` (shared sensitive rules: ApprovePayment/RejectPayment/PublishLesson/SaveTopic/SaveLesson) · `app/Mcp` (server, tools, staff payload shapes) · `app/Support` (deep modules: `Entitlement`, `Reading`/`ReadingPayload`, `TopicCard`, `PublicAssets`, `Glossary`, `Vocabulary`, `StagedUpload`, `Flashcards\Scheduler`/`Importer`/`FlashcardProgress`/`FlashcardPresenter`) · `app/Filament` · `resources/js/pages` + `resources/js/layouts` + `resources/js/components` (Inertia learner/public UI; plain reading paragraphs, no cue-sync component; `pages/Flashcards` + `components/FlashcardPlayer.tsx` for the book decks) · `resources/js/lib/audio.ts` (single transport) + `resources/js/lib/player.tsx` + `resources/js/components/AudioPlayer.tsx` (persistent learner adapter) · `resources/public-assets.json` (Vite + SW allowlist; read by `vite.config.js` and `app/Support/PublicAssets.php`) · `resources/css/app.css` (tokens) · migrations/seeders · `tests/Feature,Unit` + `tests/browser` · `docs`.

Rules: one `HTMLAudioElement` in the shared learner layout (persistent across in-layout navigation); never two concurrent audio elements (§13.1). The transport owns play/pause, seek, skip, rate, error/retry, and event wiring; the learner adapter adds progress/completion and the public pages add no callbacks. No parallel controller/service/repository/manager per model; direct Eloquent is fine, Actions carry shared/transactional rules (§15). No speculative abstractions, public event bus, or framework-class wrappers (§15). One payload owner per shape (`TopicCard`, `ReadingPayload`); one eligibility owner (`Entitlement`).

## Eligibility and server-side enforcement (scope §8)

Eligibility (UTC, server-computed):

```text
eligible = user exists AND disabled_at IS NULL
  AND subscription.revoked_at IS NULL
  AND starts_at <= now_utc < expires_at
```

- Owner of eligibility: `App\Support\Entitlement` (server, recomputed per request) — never client state, never cached `account_status` on users (§8). `eligible()` is the request gate (disabled check, staff bypass, fresh read); `windowActive()` is the locked money predicate. Policies, middleware, and planner cross this seam; there is no second eligibility adapter.
- Public sample allowed only if topic AND lesson published AND `is_public_sample=true`; staff draft preview only via allowed panel route (§8).
- Enforcement points (each independently server-checked): page access, audio file route, progress mutations, Livewire actions, list-body exclusion (public list carries title/image/summary/category/available-levels only — no body, paid glossary, private paths, answer keys) (§8).
- Level is not a permission: every published level is allowed to an eligible subscriber (§8).
- Expiry is immediate for subsequent premium requests; already-buffered bytes are not revocable and no DRM is claimed (§8).

## Payment snapshot + approval transaction (scope §10–11)

- Snapshot owner: server. On plan select, server creates `awaiting_receipt` with immutable plan name, price (toman integer), duration days, card number, holder, bank (§10.2). Later plan/destination edits affect only later requests. Proposed commercial default (PROPOSAL, needs owner sign-off before selling): snapshot honored until final decision, no auto-timeout (§10.2, §25).
- Receipt owner: filesystem private disk (random name, re-encoded, EXIF stripped) + `payment_requests` row; file written before DB mutation, orphan cleanup job, no success shown before DB commit (§10.3). Constraints: one image JPEG/PNG/WebP ≤5MB, MIME/signature + decodability checked, suggested 6000×6000 cap; SVG/HTML/PDF/executables rejected (§10.3).
- Request owner: `payment_requests` state machine (§10.1). One open request per user (partial unique index on `awaiting_receipt`/`pending` + server rule). Pending is not editable by the student; pending creates no access (§10.1).
- Subscription truth owner: `subscriptions` current window per user (`subscriptions.user_id` unique) + immutable `subscription_events` audit; request is source of one unique event (§11.1). No financial status duplicated on users.

ApprovePayment — single shared Action used by every UI/CLI path; logic never copied into the Filament resource (§11.2). Fixed lock order in one transaction: **User (owner) → PaymentRequest → Subscription** (§11.2–11.3). Steps: staff/suspension/CSRF/self-approval checks → lock in order → idempotent approved-replay returns prior result with no new event/date → read stored snapshots → lock/create subscription → `base = current_expires_at` if window active and unrevoked else `approved_at_utc`; `new_expires_at = base + snapshot_days × 24h` (fresh purchase `starts_at` = approve time; active renewal preserves `starts_at`; clears `revoked_at`) → insert event with unique `source_payment_request_id`, before/after, duration, actor, time → mark request approved with reviewer/time + update subscription → commit; notifications only after commit (§11.2). Manual grant/revoke/reject use the same lock order and mandatory reason + event; `expires_at` is never free-form CRUD (§11.3). Replayed old approvals never reactivate a revoked subscription (§11.3).

## Private media + receipt delivery with Range (scope §16)

- Audio + receipts on a private disk outside public; covers/icons/assets may be public. Physical paths never built from raw user input; lookup via model + server path (§16).
- Audio route owner: controller (`/media/lessons/{lesson}/audio`). Checks policy + `audio_revision` first; production byte delivery via Nginx internal location + `X-Accel-Redirect` (external URL to the internal location 404s); dev uses standard file responses with Range (§16). Never load whole audio via `file_get_contents` (§16).
- Receipt route owner: policy (`/media/payment-requests/{request}/receipt`); owner + authorized staff with session only; no permanent public URL; `Cache-Control: private, no-store`; excluded from CDN/SW caches (§16, §10.3).
- HTTP contract: `GET`/`HEAD`, `Accept-Ranges`, `206`+`Content-Range` for valid ranges, `416` for out-of-range, correct seek after partial fetch; private media/account HTML/Livewire responses `private, no-store`; public fingerprinted assets long cache (§16). Errors: invalid upload → 422; unauthorized → 403/404 per route contract; invalid session → auth redirect; no debug/stack/query/secrets in production (§16).
- Public HTML caching posture (decided 2026-11-14): marketing HTML (landing, trust pages, download, install, sample) also stays `private, no-store` because every Inertia response carries a session/CSRF token and `marketing.guest` needs auth state. A guest view therefore renders PHP and persists a database session. This is deliberate until a stateless guest-marketing transport and a shared-cache policy are designed; revisit when a CDN/reverse-proxy cache is introduced or marketing traffic makes the origin cost material. Measurements and options are recorded in `plans/012-public-html-caching-decision.md`.
- Marketing boundary (owner requirement 2026-10-21): `/`, trust pages, `/download`, and `/install` are guest-only via `marketing.guest`; a signed-in request redirects to `/app/today`. `/sample` remains public because the locked learner state uses it as the free path. The app shell owns only app-local links; the landing never links into `/app`. Public SEO metadata (title, description, canonical, Open Graph, Twitter, JSON-LD) is rendered in the root template from a controller-supplied allowlist and mirrored by the client `SeoHead` on every Inertia visit, keyed by `data-inertia`/`head-key` so tags replace instead of accumulate.
- Request hardening: CSRF, secure/HttpOnly/SameSite session cookie, session regeneration, hashing, rate limits (proposed: login 5/min per account+IP, uploads 5/min, payment creates 10/day per user — tune with real sample, §16); Livewire actions treat all data/IDs as untrusted; no secrets/answer keys in hydration (§16).

## Agent content upload over MCP (owner request 2026-11-08; decision in `docs/adr/0004-mcp-content-upload.md`)

- One server, additive transport: `POST /mcp/content` (official `laravel/mcp`, Streamable HTTP) and `PUT /mcp/uploads/{upload}` in `routes/ai.php`. The file loads outside the web stack, so these routes have no session cookie and no CSRF token; authority is the bearer token only.
- Identity owner: `mcp_tokens` (staff user FK, SHA-256 token hash, abilities, `expires_at`, `revoked_at`, coarse last-used audit). Issuance is server-shell only (`mcp:token issue`); no public token management. Abilities: `content:read`, `content:write`, `content:publish`; default read+write. Active staff is re-checked per request via `Entitlement::staff`.
- Content writes: `save-category` (upsert by slug), `save-topic` (upsert by slug; generated cover when absent; license record required for staff covers), `save-lesson` (upsert by topic+level). Draft-only: existing published/archived rows are refused; published/archived edits stay panel or archive→to-draft→edit→publish.
- Binary owner: `App\Support\StagedUpload`. `begin-upload` returns a single-use encrypted token bound to the MCP token + upload id (30 min TTL); the agent PUTs raw bytes with `X-Upload-Token`, then passes `upload_id` to `save-lesson`/`save-topic`. The endpoint streams to the private disk with a byte cap, validates the same MP3 signature / cover bytes and dimensions as the panel, and marks consumption so the id cannot be replayed. Abandoned staging files are cleaned by `mcp:cleanup-uploads` every fifteen minutes.
- Publishing owner: `App\Actions\PublishLesson` (unchanged). `transition-content` is the only status changepoint and needs `content:publish`; a draft lesson publish always needs `confirm_review=true`, which records the token owner as reviewer with the current UTC time. The MCP path records a review only on that explicit confirmation; a content edit clears an earlier review.
- Payload owner: `App\Mcp\ContentPayload`; private audio paths never appear in tool JSON (only readiness/revision). Tool calls log `mcp.tool` metadata without arguments or bytes. Responses are `Cache-Control: private, no-store`. No learner-visible route, public API, or second auth client is added.

## PWA and TWA boundaries (scope §18)

- PWA owner: manifest (`lang=fa`, `dir=rtl`, `display=standalone`, `start_url=/app`, proper scope, standard + maskable icons) + limited service worker. `resources/public-assets.json` is the single precache allowlist (Vite inputs with a `precache` flag + static public entries); a `precache: true` input missing from the build manifest fails the SW route instead of silently dropping assets. SW precaches only the public offline page, its icons, and the manifest; the app shell (Vite JS/CSS/fonts) stays network-only and relies on the immutable `/build/` HTTP cache. All data-bearing navigations, auth, Livewire, admin, receipts, placement, progress, and media are network-only — even sample audio is NOT in the v1 offline cache (§18.1). Offline shows a public "connect to continue" page with retry; never serves the last premium/account page as fallback (§18.1). SW versioning + old-cache eviction (empty `SW_VERSION` derives the cache name from the build manifest); no forced reload mid-receipt/exam/playback (§18.1). Logout clears player + page state; back/forward + bfcache must not show prior-account private data without session recheck (proved with two accounts + real logout, §18.1).
- TWA/APK owner: Bubblewrap wrapper of the same HTTPS site; no second frontend, no Node API (§18.2). Proposed package ID `com.fastenglishpodcast.app` (PROPOSAL — finalize before first release, §18.2). `/.well-known/assetlinks.json` matches real release package + SHA-256; domain/signing verified early on reachable staging + real Android, with verification failures/toolbar behavior documented (§18.2). Keystore/passwords/recovery outside Git with independent backup + named owner (§18.2). Download from project domain; versioned file with versionCode/versionName/date/size/SHA-256 on the page (§18.2). Ordinary web changes need no new APK; package/manifest/signing changes have their own release path (§18.2). Online-only app; no background-audio guarantee across devices (§18.2).

## Flashcards — book decks and lesson vocabulary (owner clarification 2026-11-15)

- Content owner (books): `flashcard_books` → `flashcard_units` → `flashcards`, imported from the curated AEF dataset by `App\Support\Flashcards\Importer` via `php artisan flashcards:import`. Stable identities: book slug, `(book_id, number)`, card `external_id`. A re-import upserts content and never touches learner state. `flashcards.image_path` is nullable and no longer rendered or served: cards are text-first.
- Content owner (word clips): `word_audio` — one row per lower-cased `word_key` (unique), private `path`, `source`/`voice`/`seed`, `status` draft/approved/rejected, reviewer fields. Written only by `php artisan flashcards:audio:import` from a reviewed manifest; the workflow lives in `docs/ops/FLASHCARD_AUDIO_FA.md`. A missing or non-approved row means a silent card, never a broken page.
- Learner owner (book decks): `user_flashcards` (one row per user/card; phase, step, due_at, interval_days, ease_factor, reps, lapses, last_rating) and the append-only `flashcard_reviews` (before/after snapshot, `was_new`, `session_id`, `client_review_id`). Unique `(user_id, flashcard_id)` and `(user_id, client_review_id)`; indexes `(user_id, phase, due_at)` and `(user_id, last_rating)`. Reviews are owner-scoped; another learner's schedule is never exposed.
- Learner owner (lesson decks): the lesson glossary is the deck (`App\Http\Controllers\LessonFlashcardController`); grading creates/updates the same `vocabulary_words` row the notebook reads, so one word has one schedule. No second deck table and no second SRS for vocabulary. A known word stays known on Good/Easy and reopens on Again/Hard.
- Scheduler owner: `App\Support\Flashcards\Scheduler` for book decks — a pure two-grade SM-2 (Again/Good) with learning steps 1/10 minutes, one-day graduation, relearning at 10 minutes, ease 2.5 (floor 1.3, ceiling 3), maximum interval 180 days. `App\Support\SpacedRepetition` (Again/Hard/Good/Easy) for lesson decks and the notebook. `StudyDay` owns the Asia/Tehran day boundary for daily limits and "reviewed today"; due timestamps stay UTC.
- HTTP: `/app/books` (shelf), `/app/books/{book:slug}` (book), `/app/books/{book:slug}/{unit}` (unit hub: progress + deck/exercise paths), `/app/books/{book:slug}/{unit}/flashcards` (player, `?only=again` retry), `/app/books/{book:slug}/{unit}/flashcards/results` (two buckets), `/app/flashcards/review` (daily due queue), `POST /app/flashcards/reviews` (idempotent book event), `/app/lessons/{lesson}/flashcards` (glossary deck), `POST /app/lessons/{lesson}/flashcards/reviews` (four-grade vocabulary event). The old `/app/flashcards...` book URLs redirect to the matching books URL. All pages and mutations are behind `auth + reject.disabled + subscribed`; the lesson controller also re-checks lesson and topic publication.
- Media: `/media/flashcards/{flashcard}/audio`, `/media/words/{wordAudio}/audio` (approved only) and `/media/flashcard-books/{book:slug}/cover` serve from the private disk after the same gate, with `private, no-store`; card content, word clips and covers never enter the service-worker cache, public HTML, Inertia payloads beyond the eligible page, or logs. There is no card-image route.
- Import: source dataset outside Git; card audio is copied after an MPEG sniff; the book cover prefers `dataset/index.json` over the dataset contact sheet. Word clips arrive through the manifest importer after review. Learner state is separate, so content fixes are safe.

## Book exercises (owner request 2026-11-15)

- Content owner: `exercise_sets` (one set per unit or lesson, stable `external_id`, Persian instructions, status draft/published/archived) → `exercise_items` (type, prompt, client options, server answer, explanation, position). Imported by `App\Console\Commands\ImportExercises` via `php artisan exercises:import`. Stable identities: set `external_id`, item `(set_id, external_id)`. A re-import upserts and never deletes an item, so an existing attempt keeps its answers.
- Learner owner: `exercise_attempts` (user, set, score, total, submitted_at) and `exercise_answers` (unique `(attempt_id, item_id)`, raw response, `is_correct`). Owner-scoped: another learner's attempt is never resolved.
- Marking owner: `App\Support\Exercises\Grader` — a pure function per type (choice index, normalized fill text, joined order sentence). `ExercisePresenter` owns the two allowlists: the pre-submit item shape has no `answer`/`explanation_fa`; the result shape adds both.
- HTTP: `GET /app/books/{book:slug}/{unit}/exercises` (intro + questions + last attempt), `POST` on the same path (one submission, throttle 60/min), `GET .../exercises/{attempt}` (result). The hub links the set; the exercise pages return to the hub. All behind `auth + reject.disabled + subscribed`; the controller re-checks book/unit publication and attempt ownership.
- Content import: reviewed JSON targeting `book`+`unit` or `lesson_id`, with `--draft` and `--dry-run`. An unknown type, a bad answer index, a duplicate id/position or a missing target fails the whole file with a non-zero exit and no writes. Contract: `docs/EXERCISES.md`.
- Progress owner: `App\Support\Exercises\ExerciseProgress` — per-book and per-unit aggregates plus the one Today task. Constant query shape: one set query + one attempt query per page, grouped in PHP; no per-unit or per-attempt query. Today calls it only for an eligible learner, so the daily-plan query budget moved from 13 to 14 (the no-books fixture pays one set lookup).

## Cross-track review hub (owner request 2026-11-15)

- Read-only owner: `App\Http\Controllers\ReviewController` → `Review/Index`. It composes three existing read models — due vocabulary (`vocabulary_words`), due book cards (`FlashcardProgress::dueCount`/`nextDueAt`) and exercise mistakes (`ExerciseProgress::mistakes`) — and never writes.
- `/app/review` is behind `auth + reject.disabled + subscribed`. The primary action is deterministic (words → cards → exercise retry); an empty hub links to the notebook.
- `ExerciseProgress::mistakes` reads the latest attempt per set (`max(id) group by set_id`), counts wrong answers and returns the latest set's retry/result URLs; lesson-only sets are excluded from links because the exercise routes are book-scoped.
- Today adds one `cards` task when book cards are due (one due-count query for an eligible learner), moving the daily-plan query budget from 14 to 15; the budget test records it.

## TED Talk reader (owner request 2026-11-21)

- `ted_talks` is a first-class content table, not a `lessons.level` value: nullable unique `topic_id`, own slug, private `audio_path`, `audio_revision`, cues (`segments`), ten words, licensed cover, source/licence record, and the same draft/published lifecycle. Sentence cues are validated server-side (`App\Support\TedContent`): non-negative monotonic millisecond times and at most ten unique words.
- Routes: `GET /app/topics/{topic:slug}/ted` (`ted.show`) and `GET /media/ted-talks/{talk}/audio` (`media.ted.audio`). The page controller authorizes before building the payload; the audio controller re-checks publication and policy, then uses the shared `ServesPrivateAudio` trait (Range/206/416, private no-store; nginx `X-Accel-Redirect` in production). Lesson audio uses the same trait.
- The reader payload is an allowlist: topic identity, talk metadata, `audio_url`, segments and words. `audio_path` is hidden on the model and never serialized.
- The persistent player accepts a `kind: 'ted'` track; its identity is `ted:<id>:<revision>` and `canSave` is false, so TED listening never posts lesson progress. The talk is replaced when another track binds and survives in-app navigation.
- Import: `php artisan ted:import <pack>` reads `manifest.json` + one `final.json` per talk, copies audio to the private disk and the cover to the public disk under content-addressed names, and upserts. Draft by default; `--publish --reviewer=<staff email>` records the review.

## Data constraints (summary; full table in scope §14)

Models added only with their slice — no full schema before the first real page (§14). UTC timestamps, FKs everywhere. Required uniques: `lessons(topic_id,level)`, `lesson_progress(user_id,lesson_id)`, `bookmarks(user_id,topic_id)`, `vocabulary_words(user_id,word)` (case-folded), partial unique open `payment_requests(user_id)`, unique-when-not-null `subscription_events(source_payment_request_id)`, `subscriptions(user_id)`, `placement_answers(attempt_id,question_id)`, `placement_questions(test_id,position)`, partial unique in-progress `placement_attempts(user_id)`, single `placement_tests.is_current=true` (published only), single active bank destination. Checks: allowed level/status sets, positive plan/snapshot amounts and durations, expiry after start, goal in (5,10,15), SRS grade in (again,hard,good,easy). Indexes: status/published_at, topic/category, payment queue (status, created_at), progress (user_id, updated_at), vocabulary (user_id, due_at). No cascade delete over financial/progress/vocabulary history; archive/disable is the default. Secrets/answer keys/internal notes/private paths hidden from public serialization (hidden ≠ DTO allowlist).

New tables (R-slice): `vocabulary_words` (user FK restrict, word, word_key lowercased, meaning_fa, example_en nullable, lesson/topic FK nullable set-null, status learning/known, ease_factor, interval_days, repetitions, lapses, due_at, last_reviewed_at) owned per user via `VocabularyWordPolicy`. `users.daily_goal_minutes` smallint default 10. Daily plan (`App\Support\DailyPlan`) is computed, never stored: continue-lesson from latest `lesson_progress`, listen task from the same lesson audio, review task from due vocabulary count, next-lesson by `preferred_level` fallback newest; progress from persisted completions + reviewed-today count. Vocab/plan payloads never enter SW caches, logs, or Inertia hydration beyond the eligible reader page.

Flashcard tables (2026-11-15): `flashcard_books` (slug unique, study_config JSON, status draft/published/archived), `flashcard_units` (unique `(book_id, number)`), `flashcards` (`external_id` unique, content + private audio path; `image_path` optional and unused), `user_flashcards` (unique `(user_id, flashcard_id)`, phase/ease/interval checks), `flashcard_reviews` (unique `(user_id, client_review_id)`, rating/phase checks, append-only), `word_audio` (unique `word_key`, private path, status draft/approved/rejected check, source/voice/seed/duration/reviewer fields). Exercise tables (2026-11-15): `exercise_sets` (unique `external_id`, unit-or-lesson check, status check), `exercise_items` (unique `(set_id, external_id)` and `(set_id, position)`, type check), `exercise_attempts` (user/set FKs, score/total), `exercise_answers` (unique `(attempt_id, item_id)`, `is_correct`). FKs cascade on content/user deletion; content is curated and normally archived, never hard-deleted. The review log carries ids and schedule snapshots only — no card text, media path, or free-form note.

## Owner-approved frontend migration 2026-10-10 (M0–M5 delivered 2026-10-11; M6 delivered 2026-11-13 — history above preserved)

See `docs/adr/0002-inertia-react-learner-frontend.md` for the binding decision. What changes: public + learner HTML transport becomes Inertia 3 + React 19 + TypeScript + Tailwind 4 + shadcn/ui (one learner frontend); single permanent light theme (Modern Hybrid light exact table in the ADR; dark/system/sepia superseded for learner/public surfaces). What stays: runtime/topology (one Laravel app, one DB, one origin), eligibility formula, enforcement points, snapshot/approval transaction, private media + Range contract, PWA/TWA boundaries, data constraints, and the shared-Action rule. Filament 5 panel (`/admin`) stays with its internal Livewire isolated; learner Livewire/Alpine artifacts (`app/Livewire`, learner Blade layouts/views, `reader-player.js`, `theme.js`, `wire:navigate`, `@persist`, pre-paint/`fe-theme`/appearance radios) are removed only after per-slice parity proof. State-ownership deltas: "Forms + validation" owner becomes Inertia + Laravel (server still the reference; error bags replace Livewire validation responses); player state owner becomes the React persistent-layout audio element (same single-element, no-`timeupdate`-to-server rule); "Theme" row becomes fixed single light (no stored choice); list-body exclusion and answer-key/correct-option/scoring-rules/receipt-path secrecy extend from "Livewire payloads/hydration" to "Inertia props" with identical force. No parallel REST API, no Node API server, no second auth client.
