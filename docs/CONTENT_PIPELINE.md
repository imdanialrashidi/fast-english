# Content Pipeline — Podcast Slice 3

Durable documentation for the Episode Content Package pipeline: the
versioned package contract, JSON Schema, local validation, the
Staff-authenticated import transport, transaction guarantees, version
rules, audit history and the CLI. Companion to `docs/PODCAST_DOMAIN.md`
and `docs/ARCHITECTURE.md`.

## 1. Scope

Make adding a Podcast Episode simple enough for one backstage
administrator:

```text
Create template
→ add artwork, audio, transcripts and vocabulary
→ validate locally
→ inspect dry-run
→ import as Draft
→ preview and publish later in Admin Console
```

The database mapping is unchanged (Slice 2):

| Package concept  | Database collection   |
| ---------------- | --------------------- |
| `categoryKey`    | `categories.key`      |
| Episode          | `topics` (status = Episode publication state) |
| Variant          | `lessons` (unique `topic + level`) |
| Vocabulary       | `lesson_vocabulary`   |
| Student Progress | `lesson_progress` (never modified) |

No parallel Episode collections; no renames. Imported content is always
`draft`; the pipeline never publishes.

## 2. Package layout (directory contract)

```text
content-packages/<episode-slug>/
├── episode.json          ← the manifest
├── README.md             ← editor notes (generated by the template)
├── artwork/
│   ├── square.png|jpg|webp   ← required Episode artwork (≤5 MB)
│   └── hero.png|jpg|webp     ← optional wide hero (≤5 MB)
├── audio/
│   ├── b1.mp3|m4a        ← one audio per Variant (≤10 MB)
│   └── c1.mp3|m4a
└── transcripts/
    ├── b1.md             ← UTF-8 Markdown per Variant
    └── c1.md
```

- One or more Variants; the package does not require every CEFR level.
- Assets are never embedded in JSON; no Base64 media.
- Transcripts are UTF-8 Markdown files.
- ZIP upload is a later possibility; the directory contract is
  authoritative.

## 3. Manifest contract (version 1.0.0)

`schemaVersion: "1.0.0"` (the only supported value). The full schema is
`schemas/episode-package.schema.json` (JSON Schema **draft 2020-12**,
validated with **Ajv 2020**). Editorial rules beyond the schema live in
`shared/content-package/editorial.ts`.

Root fields: `schemaVersion`, `contentKey` (must equal
`<categoryKey>.<episode.slug>`), `contentVersion` (positive integer),
`categoryKey`, `episode`, `variants` (1–6, unique CEFR levels, CEFR
enum `A1..C2`). Episode fields: `slug`, `titleEn`, `titleFa`,
`descriptionFa`, `artworkSquare`, optional `heroImageWide`,
`artworkAltFa`, optional `episodeNumber`, optional `featured`.
Vocabulary entry: `term` (required), `meaningFa` (required),
`definitionEn` (required), optional `phonetic`, `partOfSpeech`,
`exampleSentence`, `pronunciationAudio`. Unknown properties are
rejected at every level (`additionalProperties: false`).

`contentKey` is the stable import identity; `contentVersion` is the
version; `packageFingerprint` (see §12) is the content identity used
for no-change/conflict detection.

## 4. CLI commands

```bash
pnpm content:new <episode-slug> [--levels A1,B1,C1]
pnpm content:validate <package-dir>
pnpm content:plan <package-dir> [--json]
pnpm content:import <package-dir> [--yes]
```

Environment for plan/import:

```text
FEP_PB_URL            e.g. http://127.0.0.1:8090
FEP_STAFF_EMAIL
FEP_STAFF_PASSWORD
```

Exit codes: `0` success · `1` validation/import rejection ·
`2` environment or tool failure (missing env, unreachable server).
`content:import` requires explicit confirmation in interactive
terminals and supports `--yes` for automation; it never defaults to
`--yes`. The CLI never prints passwords, tokens, full transcripts or
storage paths. `FEP_CONTENT_DIR` overrides the package library location
for tests.

`content:new` validates the slug, refuses to overwrite an existing
directory, prints the created paths and the next commands, generates
one minimal B1 Variant by default (`--levels A1,B1,C1` supported) with
`TODO_REPLACE` placeholders, and never modifies the database. The
generated template intentionally fails strict import until the
placeholders and assets are provided.

## 5. Local validation architecture

Pure pipeline modules (browser-safe, typechecked, unit-tested) in
`shared/content-package/`:

| Module | Responsibility |
| --- | --- |
| `constants.ts` | limits (artwork 5 MB, audio 10 MB, pronunciation 2 MB, transcript 50 000 chars) and documented thresholds |
| `types.ts` | manifest/plan/diagnostic types |
| `schema.ts` | Ajv 2020 validation against the JSON Schema |
| `normalize.ts` | slug/content-key rules, transcript normalization, canonical vocabulary normalization (Slice 2) |
| `editorial.ts` | deterministic copy checks (blocking errors + warnings) |
| `checksums.ts` | pure-JS SHA-256 (NIST-vector tested), canonical JSON, package fingerprint, plan-state hash |
| `versioning.ts` | version-state machine and deterministic diff planning |
| `serialize.ts` | bounded, sanitized diagnostic serialization |

Node-only modules in `scripts/content/` (never imported by app
bundles): `paths.mjs` (safe resolution + symlink escape), `assets.mjs`
(image-size + music-metadata + deterministic MP3/M4A duration
parsers), `transcript` handling, `parser.mjs` (orchestrator),
`template.mjs`, `auth.mjs` + `transport` (staff login, multipart),
`cli.mjs` (commands), `fixtures.mjs` (deterministic test-safe PNG/MP3
generation).

Validation order: manifest JSON → JSON Schema → identity contract
(contentKey = categoryKey.slug) → structural path safety → asset
inspection (signatures, geometry, durations, transcript normalization)
→ editorial checks → checksums → fingerprint.

`ValidationResult = { valid, errors[], warnings[], package? }` with
stable diagnostic codes (`code`, `severity`, `path`, `message`,
`suggestion`) suitable for the future Admin UI.

## 6. Editorial diagnostics

Blocking errors: empty titles/descriptions/summaries, placeholder
values, empty vocabulary meaning/definition, unsupported level,
duplicate Variant levels, duplicate normalized vocabulary terms, empty
transcript, headings-only transcript, forbidden transcript constructs,
unsafe paths, unsupported/corrupt media, unreadable audio duration.

Warnings (documented thresholds): titles > 60 chars, description < 40
chars, transcript < 1000 chars, missing example sentence, missing
phonetic, Variant without vocabulary, missing optional hero,
non-square artwork (±8 px), artwork < 512 px, hero not landscape, hero
ratio outside 1.4–2.1, repeated title words, generic artwork alt, > 20
vocabulary entries.

No AI, no subjective style judgement.

## 7. Transcript handling

Read as UTF-8, then normalize: strip BOM, CRLF/CR → LF, trim trailing
whitespace per line, collapse 3+ blank lines to one, trim leading/
trailing blank lines. Punctuation, headings, emphasis and paragraph
structure are preserved. Stored as `lessons.body` (the existing Variant
transcript field — no second field; documented choice).

Rejected: `<script>/<iframe>/<object>/<embed>`, `javascript:` links,
empty or headings-only content, > 50 000 characters. Markdown is not
converted to HTML during import (the Product renders the transcript as
escaped text; the pipeline only guarantees safe, normalized Markdown).

## 8. Artwork validation

Programmatic inspection (signature + `image-size`): JPEG/PNG/WebP only,
≤ 5 MB, extension/MIME cross-check, width/height required. Square
artwork must be within ±8 px of square (warning), recommended minimum
512 px (warning). Hero must be landscape (warning) with a 16:9-ish
ratio warning (1.4–2.1). Zero-size/corrupt files are rejected. No
visual interpretation, no composition scoring.

Codes: `ARTWORK_NOT_SQUARE`, `ARTWORK_TOO_SMALL`, `HERO_NOT_LANDSCAPE`,
`IMAGE_UNSUPPORTED_TYPE`, `IMAGE_CORRUPT`, `IMAGE_EXTENSION_MISMATCH`.

## 9. Audio validation and duration extraction

Formats: MP3 (`audio/mpeg`) and M4A (`audio/mp4`) — OGG/WebM remain
valid via the dashboard but are not importable in this slice
(documented limitation). Limits: ≤ 10 MB per Variant, ≤ 2 MB
pronunciation. The **duration is extracted from the bytes**, never from
the manifest and never typed by hand; it is stored into the existing
`lessons.audio_duration_seconds`. `estimated_minutes` is derived
server-side as `clamp(ceil(duration/60), 1, 120)`.

The CLI uses `music-metadata` (maintained, pure JS) with a
deterministic MP3 frame parser / M4A `mvhd` parser as fallback (needed
for synthetic fixtures and unusual encodings). The server hooks
implement the same parsers (authoritative). CLI/server parity for
durations and fingerprints is asserted by the smoke suite.

Codes: `AUDIO_UNSUPPORTED_TYPE`, `AUDIO_DURATION_UNREADABLE`,
`ASSET_SIZE_EXCEEDED`, `AUDIO_PATH_REUSED`.

## 10. Vocabulary validation

Canonical Slice 2 normalization (trim, collapse whitespace, lowercase
— `normalizeVocabularyTerm`). Per Variant: reject duplicate normalized
terms, preserve the original display term, preserve declared order
(`sort_order = index`), validate pronunciation files (MP3/M4A ≤ 2 MB).
No automatic generation, no AI translation, no invented definitions.

## 11. Safe path resolution

All package-relative paths must satisfy structural rules (no `..`,
absolute, drive, UNC, backslash, null-byte or encoded-traversal
segments) **and** filesystem containment: the real (symlink-resolved)
path of every asset must stay inside the real package root. A symlink
inside the package pointing outside is rejected
(`PACKAGE_PATH_ESCAPE`). The server re-validates the same rules for the
multipart field names and never touches the filesystem with them; all
import assets come from the package.

## 12. Checksums and package fingerprint

Per-asset SHA-256 over the actual bytes (artwork, hero, audio,
transcript, pronunciation). The package fingerprint is
`sha256("fep-episode-package-v1\n" + canonicalManifest + "\n" + sortedAssetLines)`
where `canonicalManifest` is JSON with sorted keys and each asset line
is `path\0size\0sha256`. It never depends on absolute paths, timestamps,
directory ordering, usernames or machine metadata. The pure-JS SHA-256
implementation is shared between the CLI and the server hooks (mirrored
in `content_import_core.pb.js`) and NIST-vector tested; the smoke suite
asserts CLI/server fingerprint parity.

## 13. Import audit collection (`content_imports`)

Additive, locked (all CRUD rules `null`). Fields: `content_key`,
`content_version`, `package_fingerprint`, `schema_version`, `status`
(planned/running/completed/failed/no_change), `summary_json`,
`error_json` (bounded, sanitized), `imported_by` (relation to
`staff_admins`), `started_at`, `completed_at`. Partial unique index
`(content_key, content_version, package_fingerprint) WHERE
status='completed'` — one successful import per exact package identity;
failed attempts never block corrected imports. Never stores tokens,
passwords, transcripts, audio or storage paths. Staff-only route
`GET /api/fast-english/staff/content-imports/{id}` exposes sanitized
records.

## 14. Import identity and version rules

- **New key** → create Category relation (must exist), Episode, Variant
  Lessons, Vocabulary, media, audit — all Draft.
- **Same key, same version, same fingerprint** → `no_change`, nothing
  written.
- **Same key, same version, different fingerprint** → `conflict` (409);
  fix by incrementing `contentVersion` (controlled replace is out of
  scope).
- **Higher version** → update into Draft. A published Episode moves to
  Draft together with **all** its Variants (so stale variants can never
  resurface on a later Publish); imported Variants receive the new
  content and vocabulary (old vocabulary is replaced only for imported
  Variants). Existing Progress is never modified; nothing is deleted.
- **Lower version** → `stale` (409); no rollback workflow in this slice.

## 15. Transport and transaction guarantees

### Architectural probe (required by the slice brief)

Before building the importer, a minimal disposable proof ran against
the pinned PocketBase 0.39.9 binary (`/api/fep-probe/*` routes,
removed after the probe). Result: **14/14 passed**, recorded here:

1. One multipart request carrying a manifest plus multiple files is
   received intact (string parts via `e.request.form.get()` after
   `e.request.parseMultipartForm(n)`; files via `e.findUploadedFiles()`,
   bytes via `f.reader.open()` + `toBytes()`).
2. Uploaded files assign to Topic and Lesson records
   (`rec.set('artwork_square', f)` after renaming `f.name =
   $security.randomString(16) + ext`).
3. `$app.runInTransaction(txApp => …)` commits records **and files**
   atomically (2 collection dirs gained the expected files).
4. A failing transaction rolls back **records and files**: after a
   forced unique-index violation, zero records existed and the storage
   directory file count was byte-identical to before the attempt.

Findings encoded in the implementation:

- PB 0.39 JSVM quirk: `e.request.form` is empty until
  `ParseMultipartForm` runs — call `e.request.parseMultipartForm(n)`
  first (order-independent).
- Required NumberFields reject `0` in goja (`sort_order: cannot be
  blank`) — the importer writes `sort_order ≥ 1` for topics and uses
  explicit values elsewhere.
- JSON bodies must be UTF-8 decoded (raw `String.fromCharCode` over
  the bytes mojibakes Persian text) — the core module provides
  `utf8Decode`.
- `$apis.requestInfo(e)` does not exist in 0.39.9 JSVM; read bodies
  with `toBytes(e.request.body, max)`.

### Selected transport

```text
local CLI validates and inventories Package
→ Staff-authenticated multipart request
→ Server independently revalidates authoritative fields
→ Server performs the import in one transaction
```

The server never trusts the CLI: it re-validates Staff identity
(`requireStaffAdmin` + `$apis.requireAuth('staff_admins')`), package
identity, `schemaVersion`, multipart field names (must match the
declared asset set exactly — unexpected parts are rejected), file
types/sizes/signatures, audio durations, Category existence, Episode/
Variant rules, version conflicts, duplicate vocabulary, publication
target (always draft) and record relationships.

### Stale-plan protection

The plan route returns `planStateHash` (SHA-256 over the
version-relevant facts: Episode status/version, per-Variant
status/version, last completed fingerprint, Category existence). The
execute route requires a valid `planStateHash` (`400 plan_state_required`
when missing or malformed — direct execution without a plan is not
allowed), recomputes it against current state and rejects with
`409 plan_stale` when the database changed since the plan.

### Transaction vs compensation

True transactions are proven (probe above): the whole import runs in
one `$app.runInTransaction`. A failed import leaves **no** Episode,
Variants, Vocabulary, media files or completed audit — the audit record
is written as `failed` with bounded sanitized diagnostics. Audit writes
happen outside the content transaction on purpose: a failure is always
recorded, and a crash between commit and audit-complete leaves a
`running` record that the next execute supersedes as `failed`.

## 16. Import application rules

`categoryKey → categories.key` (must already exist — no silent
creation; `--create-category` out of scope). `episode → topics`,
`variant → lessons`, `vocabulary → lesson_vocabulary`. Imported
Episode/Variant status: `draft`. Existing Progress never modified.
Existing published content is never deleted; existing published media
stays available until a later explicit Publish replaces it. CEFR order
remains canonical. Artwork resolution follows Slice 2
(`thumbnail_override → artwork_square → Product fallback`).

## 17. Staff routes

```text
POST /api/fast-english/staff/content-import/plan      (read-only diff)
POST /api/fast-english/staff/content-import/execute   (multipart import)
GET  /api/fast-english/staff/content-imports/{id}     (sanitized audit)
```

Both write routes use `requireStaffAdmin()` and
`requireAuth("staff_admins")`; Students, legacy Operators and
unauthenticated callers are rejected. Per-staff in-memory rate limits
(plan 30/min, execute 30/min). Responses never include storage paths,
internal stack traces or tokens. The plan route never mutates anything
(database, files, audit records — asserted by the smoke suite).

## 18. Dry-run behavior

`content:plan` runs full local validation, authenticates as Staff, and
prints a deterministic diff (Package/Category/Episode/Variants/
Vocabulary/Publication/Result) or `--json` for the future Admin
Console. Zero mutation is proven by the smoke suite (record counts and
storage file counts before/after).

## 19. Security model

- CLI authenticates as `staff_admins` only (never superuser).
- No credentials committed or printed; auth failures give safe
  messages; inactive Staff and Student credentials are rejected.
- The server is the security boundary; the CLI's validation is
  editorial convenience.
- Imported Draft content is hidden from every public Student route
  (proven: draft detail → 404, draft list entries absent).
- Diagnostics are bounded (≤ 50 entries, ≤ 500 chars each) and
  sanitized (secrets/paths replaced with `[REDACTED]`).
- Files are stored under randomized names in PB-managed storage.

## 20. Known limitations

- OGG/WebM audio is not importable (dashboard-managed only).
- No ZIP upload, no Admin Import UI, no publishing UI (later slices).
- Production Caddy limits `/api/*` bodies to 6 MB; large multi-variant
  packages exceed this. The CLI targets the PocketBase port directly;
  raising the Caddy cap or staging uploads is a deployment concern for
  the production-import rollout (out of scope here).

## 22. Admin Content Studio import (Podcast Slice 4)

- **ZIP ingestion decision (proven constraint):** the pinned PB 0.39.9
  JSVM exposes no ZIP/inflate module (probed live: `require('zip')`,
  `archive/zip`, `compress/zlib`, `jszip` → "Invalid module"; no
  TextDecoder/atob). The Admin Console therefore parses the operator's
  package ZIP **in the browser** with a bounded adapter
  (`shared/content-package/zip.ts` + `zipPackage.ts`, pure TS, unit
  tested): central-directory parser, stored + deflate (platform
  `DecompressionStream('deflate-raw')`), rejects traversal, symlinks,
  unsupported methods, > 64 entries, per-entry > 12 MB and total
  uncompressed > 60 MB. It produces **exactly the Slice 3 internal
  representation** (manifest + asset inventory) and feeds the existing
  Staff plan/execute routes unchanged — the server remains the security
  boundary and re-validates every part from the actual bytes. No second
  schema; CLI/Admin parity asserted by `smoke:content-admin` (ZIP path)
  and the shared validation modules used by the report are the CLI's own
  browser-safe layers.
- **Staff Content Studio routes** (`server/pb_hooks/content_admin_routes.pb.js`
  + `content_admin_core.pb.js`): bounded category/episode/variant/
  vocabulary routes (create/edit/publish/archive/feature/reorder),
  artwork/hero/audio/pronunciation upload+remove with server-side
  signature/size/duration validation, transcript save with the shared
  normalization rules, an authoritative readiness evaluator
  (errors block publish; warnings don't; legacy-published content reads
  ready with an explicit republish notice), Staff-only draft preview and
  media routes (artwork/audio with Range/206, pronunciation; private,
  no-store; no storage names in responses), and recent import history.
- **`content_operations` audit collection** (migration 1700000025):
  publish/archive/media-replacement/creation operations with bounded
  sanitized detail and the acting Staff id. Ordinary draft text edits are
  not audited; imports keep the dedicated `content_imports` audit.
- **planStateHash in the UI:** the Admin executes only with the exact
  hash returned by the plan; a 409 `plan_stale` triggers an automatic
  re-plan that is NEVER auto-executed — the operator must confirm the
  recalculated plan explicitly. `conflict`/`stale`/`rejected` plans are
  shown with clear Persian copy and a disabled confirm action.
- **Preview policy:** Draft content is never marked Published to preview
  it; the Staff preview API serves a sanitized representation and the
  media routes require `staff_admins` on every request. Students receive
  403/404 for every draft surface (asserted by smoke + e2e).
