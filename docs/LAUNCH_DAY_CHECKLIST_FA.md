# چک‌لیست روز راه‌اندازی — Fast English Podcast

> این چک‌لیست برای روزی است که ثبت‌نام عمومی باز می‌شود. مسئولیت‌ها بین **مالک**، **اپراتور** و **مسئول فنی** تقسیم شده است. هر مورد باید با شواهد تیک بخورد؛ هیچ‌چیز فرض نمی‌شود. راهنمای کامل: `docs/OPERATOR_MANUAL_FA.md` و `docs/TECHNICAL_OWNER_RUNBOOK_FA.md`.

---

## فاز ۰ — قبل از باز کردن ثبت‌نام (روزهای قبل)

### مالک

- [ ] تصمیم نهایی دربارهٔ طرح‌ها و قیمت‌ها ثبت شده (ماهانه ۲۹۹٬۰۰۰ / سه‌ماهه ۸۰۷٬۳۰۰ تومان — **بدون طرح سالانه**)
- [ ] مقصد کارت‌به‌کارت واقعی تعیین شده: شمارهٔ کارت، نام دارنده، نام بانک، راهنمای کوتاه انتقال، «زمان تقریبی بررسی» (پیش‌فرض «حداکثر تا ۲۴ ساعت»)
- [ ] کانال پشتیبانی/همکاری (آدرس https/mailto/tel) تعیین شده — اگر تعیین نشده، لندینگ صادقانه «هنوز اعلام نشده» نشان می‌دهد
- [ ] متن حریم خصوصی و قوانین نهایی تأمین شده (تا آن زمان صفحات با برچسب «نیازمند بازبینی» می‌مانند)
- [ ] سیاست رد/بازگشت وجه و نگهداشت رسید مصوب شده
- [ ] هویت اپراتورها مشخص و تعدادشان تأیید شده

### مسئول فنی

- [ ] سرور خریداری شده، DNS هر چهار نام (اصلی/www/app/admin) به سرور اشاره می‌کند
- [ ] پرت‌های ۸۰/۴۴۳ از بیرون بازند
- [ ] فایل اسرار سرور ساخته شده (root:root 0600) — هرگز در گیت
- [ ] نصب اول انجام و تأیید شده: `install.sh`، `configure.sh`، صحت systemd/Caddy
- [ ] **پشتیبان اولیهٔ تأییدشده قبل از اولین استقرار**: `bash deploy/backup.sh`
- [ ] اولین نسخه استقرار یافته: `bash deploy/deploy.sh <bundle>` (خروجی ۰)
- [ ] آزمایش بازیابی (restore drill) روی نمونهٔ جداگانه سبز است
- [ ] مقصد پشتیبان خارج از سرور (S3 یا معادل تأییدشده) پیکربندی و با drill تأیید شده — پشتیبان فقط روی سرور **کافی نیست**
- [ ] `ops-check.sh` خروجی ۰ می‌دهد؛ کرون روزانه وصل است
- [ ] دموی بانک سؤال تعیین سطح هرگز در تولید نصب نشده؛ بانک بازبینی‌شده (در صورت تأمین) با ابزار محافظت‌شده نصب و «دقیقاً ۲۰ سؤال فعال» تأیید شده
- [ ] تست اندروید روی دستگاه فیزیکی انجام شده (نصب، ورود، بارگذاری رسید، تعیین سطح، پخش صوت، حفظ پیشرفت) — اگر انجام نشده، **گیت باز می‌ماند**
- [ ] شماره تماس/مسیر ارجاع فنی و مالک ثبت شده

### مالک + مسئول فنی (پیکربندی کسب‌وکار در پنل)

- [ ] «تنظیمات» ← «تنظیمات کسب‌وکار»: دو طرح فعال با قیمت/مدت درست
- [ ] مقصد پرداخت ثبت و **فعال** است؛ شمارهٔ کارت و راهنما دقیقاً همان مقادیر واقعی‌اند
- [ ] کانال پشتیبانی/همکاری وارد شده
- [ ] طرح‌ها در لندینگ و صفحهٔ پرداخت تست شده (تازه‌سازی صفحه — بدون rebuild)
- [ ] اولین Staff Admin ساخته شده (`staff-bootstrap`)؛ رمز ≥۱۲ نویسه

### اپراتور

- [ ] حساب Staff Admin خود را دریافت و ورود/خروج را تمرین کرده
- [ ] راهنمای اپراتور و برگهٔ راهنمای سریع را خوانده
- [ ] مسیر کامل پرداخت را در **محیط تست** با حساب تست پردازش کرده (تأیید و رد با دلیل)

## فاز ۱ — لحظهٔ راه‌اندازی

### مالک

- [ ] اعلام رسمی باز شدن ثبت‌نام (کانال مصوب)
- [ ] شمارندهٔ درخواست‌ها را با اپراتور هماهنگ کرده

### اپراتور

- [ ] وارد پنل مدیریت شده؛ «داشبورد» را باز گذاشته
- [ ] «پرداخت‌ها» ← «در انتظار بررسی»: صف خالی است
- [ ] هر درخواست جدید طبق SOP بررسی و بدون تأخیر تصمیم‌گیری می‌شود (تأیید/رد با دلیل)
- [ ] پیام‌های پشتیبانی با الگوهای مصوب پاسخ داده می‌شوند

### مسئول فنی

- [ ] `bash deploy/ops-check.sh` هر چند ساعت — خروجی ۰
- [ ] لاگ خطاها: `journalctl -u fast-english-pocketbase` و لاگ‌های Caddy (جستجوی 5xx)
- [ ] پشتیبان خودکار شبانه و کپی ۰۲:۴۰ تأیید می‌شود
- [ ] آمادهٔ پاسخ به ارجاع فوری (سایت/سرور)

## فاز ۲ — نظارت بر راه‌اندازی (ساعات اول)

- [ ] **اولین ثبت‌نام واقعی** مشاهده و مسیر کامل دنبال می‌شود (اپراتور + مسئول فنی)
- [ ] **اولین پرداخت واقعی**: رسید دریافت → بررسی SOP → تأیید → اشتراک فعال → دانشجو به تعیین سطح رسید (اپراتور)
- [ ] **اولین خطای واقعی** ثبت و دسته‌بندی می‌شود (کاربری/محتوایی/فنی/امنیتی)
- [ ] خطای 5xx/هشدار سلامت: بررسی و در صورت نیاز ارجاع فوری (مسئول فنی)
- [ ] «حداکثر تا ۲۴ ساعت» بودن SLA در صفحهٔ پرداخت تأیید شده
- [ ] دانلود اندروید (در صورت انتشار) از لینک لندینگ تست می‌شود: SHA-256 مطابق metadata است (مسئول فنی)

## فاز ۳ — پایان روز راه‌اندازی

- [ ] صف «در انتظار بررسی»: هیچ درخواست بی‌پاسخی نمانده (یا همه برچسب پیگیری دارند) — اپراتور
- [ ] سلامت نهایی: `ops-check.sh` خروجی ۰ — مسئول فنی
- [ ] پشتیبان شبانهٔ اول: ایجاد و کپی تأیید شد — مسئول فنی
- [ ] گزارش روز راه‌اندازی: تعداد ثبت‌نام، پرداخت‌های تأیید/رد، مشکلات و ارجاع‌ها — مالک
- [ ] فهرست اقدامات پیگیری فردا ثبت شد (کاربران در انتظار، درخواست‌های کهنه، مشکلات باز) — مالک

## مواردی که روز راه‌اندازی «گیت باز» حساب می‌شوند (اگر انجام نشده‌اند)

- [ ] تست دستگاه فیزیکی اندروید (نصب/پخش/حفظ پیشرفت)
- [ ] مقصد پشتیبان خارج از سرور با drill تأییدشده
- [ ] متن حقوقی حریم خصوصی/قوانین نهایی
- [ ] بانک سؤال تعیین سطح بازبینی‌شده (دمو هرگز در تولید)
- [ ] محتوای نهایی (کتابخانهٔ واقعی به‌جای بسته‌های نمونه)
