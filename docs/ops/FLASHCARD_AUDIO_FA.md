# تولید صدای فلش‌کارت — Underdog Woof

وضعیت: پیاده‌شده، ۲۰۲۶-۱۱-۱۵. مرجع محصول: `docs/PRODUCT.md` (بند «Owner clarification 2026-11-15»).

**دامنه:** این مسیر فقط برای صدای **واژه‌های فلش‌کارت** است. صدای درس/پادکست، نمونهٔ عمومی، رسید، یا هر فایل دیگر از این مسیر تولید نمی‌شود. صدای درس همان ضبط انسانی می‌ماند.

## ۱. قاعدهٔ محصول

- هر مقاله/درس یک دک از واژه‌های گلاسریِ همان درس است: مقالهٔ ۱۰ واژه‌ای = ۱۰ کارت.
- **سقف تعداد واژه نداریم.** هر مقاله هر تعداد واژه که داشته باشد، همان تعداد کارت می‌شود.
- کارت متنی است؛ عکس ندارد (نه دک مقاله، نه دک کتاب).
- روی کارت: واژهٔ انگلیسی + دکمهٔ صدا. بعد از «نمایش پاسخ»: معنی فارسی، مثال، و IPA اگر داشت.
- صدا فقط برای خود واژه ساخته می‌شود، نه جملهٔ مثال و نه متن کامل.
- دک به نسخهٔ همان سطح تعلق دارد؛ هر سطح گلاسری خودش را دارد.
- اگر برای واژه‌ای صدا نداشته باشیم، کارت بدون صدا کار می‌کند؛ دکمهٔ بلندگو مخفی می‌ماند.

## ۲. ابزار

- Underdog Woof، نصب‌شده روی دستگاه تولید محتوا.
- مدل یک‌صدایی ۳۱.۷ مگابایت یا دوصدایی ۴۰.۶ مگابایت (Hugging Face: `ConwayResearch/Underdog-Woof`).
- خروجی خام: WAV مونو، ۲۴ کیلوهرتز.
- دستور پایه:

```bash
python -m underdog_woof "cappuccino" -o cappuccino.wav
```

- برای تکرارپذیری (همان متن → همان صدا) از `seed` در پایتون استفاده کن:

```python
from underdog_woof import Woof

tts = Woof()
audio = tts("cappuccino", seed=0)
tts.save("cappuccino.wav", audio)
```

- فلگ‌های سرعت/کیفیت (مثل `--steps`) را از راهنمای همان نسخهٔ نصب‌شده بردار؛ در نسخه‌های مختلف فرق می‌کند.

## ۳. مجوز

مالک در ۲۰۲۶-۱۱-۱۵ تأیید کرد که مجوز تجاری Woof گرفته شده و استفاده از خروجی آن در محصول فروشی مشکل ندارد. سند مجوز در گیت نگه داشته نمی‌شود؛ نسخهٔ امضاشده/قرارداد پیش خود مالک می‌ماند.

- دامنهٔ مجوز همان چیزی است که مالک تأیید کرده؛ این سند جای قرارداد حقوقی نیست.
- مدل/وزن‌ها را در گیت نگذار. فایل‌های صوتی تولیدشده هم asset هستند، نه سورس‌کد.

## ۴. مسیر تولید

1. واژه‌های گلاسری درس را بردار (همان ترتیبی که در درس می‌آید). هر تعداد که هست.
2. برای هر واژه یک WAV بساز.
3. گوش بده. تلفظ غلط بود: `seed` را عوض کن، یا ورودی TTS را کمی تغییر بده (نقطه/حرف بزرگ/هجی آوایی) تا درست خوانده شود؛ متن نمایشی کارت تغییر نمی‌کند.
4. WAV را به MP3 مونو تبدیل کن و بلندی را یکدست کن:

```bash
ffmpeg -y -i in.wav -ac 1 -ar 44100 -b:a 96k \
  -af loudnorm=I=-16:TP=-1.5:LRA=11 out.mp3
```

5. فایل‌های MP3 و یک `manifest.json` را در یک پوشه بگذار، مثلاً `storage/app/private/imports/word-audio/`.
6. در manifest برای هر واژه: `word`، `file`، `status` و اختیاری `duration_ms`. نام فایل مبدأ آزاد است؛ فرمان نام مقصد را خودش می‌سازد.
7. در manifest ثبت کن: voice، seed، بازبین، تاریخ.
8. فقط ردیف‌های `approved` به کارت وصل می‌شوند. `draft` و `rejected` در دیتابیس می‌مانند ولی سرو نمی‌شوند.

حجم تقریبی: هر واژهٔ یک‌ثانیه‌ای حدود ۱۰–۲۵ کیلوبایت؛ هزار واژه حدود ۱۵–۲۵ مگابایت.

## ۵. چک‌لیست کیفیت (قبل از approved)

- [ ] تلفظ با IPA یا منبع معتبر درست است.
- [ ] ابتدا/انتهای فایل سکوت زیادی ندارد (۳۰–۵۰ میلی‌ثانیه مجاز).
- [ ] مدت واژهٔ معمولی ۰.۴–۱.۵ ثانیه؛ واژهٔ بلند حداکثر ~۲.۵ ثانیه.
- [ ] بلندی یکدست است (`-16 LUFS`)، نه خیلی آرام نه کلیپ‌شده.
- [ ] مونو، ۴۴.۱ کیلوهرتز، ۹۶ کیلوبیت.
- [ ] بدون نویز، موسیقی، افکت، یا قطع‌شدگی.
- [ ] `word` و `file` در manifest با فایل واقعی یکی است.
- [ ] وضعیت `approved` و نام بازبین ثبت شده است.

## ۶. واردکردن به اپ

```bash
php artisan flashcards:audio:import storage/app/private/imports/word-audio/manifest.json
php artisan flashcards:audio:import <manifest> --dry-run   # فقط بررسی
php artisan flashcards:audio:import <manifest> --force     # کپی دوبارهٔ فایل‌ها
```

فرمان:

- JSON را می‌خواند و هر آیتم را جدا بررسی می‌کند؛ فایل گم‌شده، بزرگ‌تر از ۲ مگابایت، یا غیر-MPEG باعث خطا و خروج غیرصفر می‌شود.
- بایت‌ها را روی دیسک خصوصی در `flashcards/words/{slug}-{hash}.mp3` می‌نویسد.
- ردیف `word_audio` را با `word_key` (حروف کوچک، trim) upsert می‌کند؛ اجرای دوباره ردیف تکراری نمی‌سازد.
- وضعیت، voice، seed، duration و بازبین را از manifest می‌گیرد.
- به هیچ برنامهٔ مرور کاربر دست نمی‌زند.

## ۷. اتصال به اپ

- مدیا: `GET /media/words/{wordAudio}/audio` — پشت گیت اشتراک، `private, no-store`، Range برای پخش.
- فقط `status=approved` سرو می‌شود؛ `draft` و `rejected` ۴۰۴ می‌دهند.
- کارت‌های درس در `/app/lessons/{lesson}/flashcards` با همان SRS دفترچهٔ واژه‌ها کار می‌کنند؛ گرید کردن کارت، ردیف `vocabulary_words` را می‌سازد/به‌روز می‌کند.
- بازتولید صدا نباید وضعیت SRS کاربر را دست بزند. صدا محتواست، نه پیشرفت.
- فایل‌ها با کلید واژه شناخته می‌شوند تا اصلاح تلفظ یک واژه، کارت‌های همان واژه را در همهٔ درس‌ها به‌روز کند.

## ۸. manifest نمونه

```json
{
  "version": 1,
  "voice": "woof-one-voice",
  "seed": 0,
  "sample_rate": 24000,
  "generated_at": "2026-11-15T20:30:00+03:30",
  "items": [
    {
      "word": "cappuccino",
      "file": "cappuccino.mp3",
      "status": "approved",
      "duration_ms": 900,
      "checked_by": "erfan",
      "checked_at": "2026-11-15T20:35:00+03:30"
    }
  ]
}
```

## ۹. چه چیزهایی نه

- صدای درس/پادکست با Woof تولید نمی‌شود؛ آن صدا ضبط انسانی و بخشی از هویت محصول است.
- موسیقی، افکت، یا جملهٔ کامل روی کارت نه.
- کلون صدای افراد بدون اجازهٔ کتبی نه.
- TTS در زمان اجرا (runtime) نه؛ فایل از قبل ساخته و بازبینی می‌شود.
- تولید انبوه بدون بازبینی تلفظ نه؛ کارت با تلفظ غلط بدتر از کارت بدون صدا است.

## ۱۰. کارهای بعدی

- پنل ادمین برای `word_audio` (آپلود/بازبینی/تغییر وضعیت) به‌جای manifest دستی.
- یک کامند بررسی سلامت (`flashcards:audio:doctor`): فایل گم‌شده، کلید تکراری، MP3 خراب، مدت غیرعادی.
- اتصال خودکار لیست واژه‌های هر درس به وضعیت صدا در پنل، تا محتوای بدون صدا قبل از انتشار دیده شود.
