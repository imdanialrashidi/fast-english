# Fast English Android app (TWA)

The installable Android build is a Trusted Web Activity that opens
`https://fastenglishpodcast.ir` full-screen.

| | |
|---|---|
| Package | `com.fastenglishpodcast.app` |
| Version | `1.0.0` (versionCode `1`) |
| Min / target SDK | 24 / 36 |
| Signed APK | [`public/downloads/fast-english-1.0.0.apk`](../public/downloads/fast-english-1.0.0.apk) |
| Signing cert SHA-256 | `9F:C0:C8:96:15:DC:7A:AA:3C:F8:4A:1F:1F:9D:80:92:E0:CB:B0:57:7D:8C:74:C8:98:4E:31:3E:E7:BB:B5:AF` |
| Project | `mobile/twa` (generated by Bubblewrap CLI 1.25.0) |

The app is only installable while the domain serves a matching
`/.well-known/assetlinks.json` statement. The route reads
`TWA_PACKAGE_NAME` / `TWA_SHA256_FINGERPRINT`; production falls back to
the values above when those env vars are empty.

## Signing key

The release keystore is **not** in this repository:

```
~/.config/fast-english/android/fast-english-release.keystore
~/.config/fast-english/android/keystore.env    # store/key password, mode 600
```

Back that folder up offline. Google Play and Android identify an app by
this key: losing it means you cannot update an installed app with the same
package id. Never commit the keystore or its password file.

## Rebuild the APK

Prerequisites: JDK 17, Android SDK (platform 36, build-tools 36.1.0),
Bubblewrap CLI. On this machine JDK is `~/.local/opt/jdk-17` and the SDK is
`~/.local/opt/android-sdk`.

```bash
export JAVA_HOME="$HOME/.local/opt/jdk-17"
export ANDROID_HOME="$HOME/.local/opt/android-sdk"
export BUBBLEWRAP_KEYSTORE_PASSWORD="$(sed -n 's/^STORE_PASS=//p' "$HOME/.config/fast-english/android/keystore.env")"
export BUBBLEWRAP_KEY_PASSWORD="$(sed -n 's/^KEY_PASS=//p' "$HOME/.config/fast-english/android/keystore.env")"

cd mobile/twa
npx --yes @bubblewrap/cli@1.25.0 build --skipPwaValidation
```

Bubblewrap writes `app-release-signed.apk` and `app-release-bundle.aab` in
`mobile/twa/`. For a new version, raise both values in
`twa-manifest.json`, regenerate the project with
`bubblewrap update --skipVersionUpgrade` (then fix `versionName` if it was
preserved from the old build), and rebuild.

## Publish a new APK

1. Copy the signed APK to `public/downloads/fast-english-<version>.apk`.
2. Measure it:
   ```bash
   stat -c %s public/downloads/fast-english-<version>.apk
   sha256sum public/downloads/fast-english-<version>.apk
   ```
3. Update the production defaults in `config/release.php` (version,
   versionCode, date, size, SHA-256, file URL) and redeploy.
4. If the signing key or package changes, update
   `config/pwa.php` (`twa_fingerprint`) **before** shipping the APK, or
   Android will open it in a browser tab instead of full-screen.

## Verify

```bash
curl -fsS https://fastenglishpodcast.ir/.well-known/assetlinks.json
apksigner verify --print-certs public/downloads/fast-english-1.0.0.apk
```

The certificate digest printed by `apksigner` must match both the
assetlinks fingerprint and the app's real installation. Install on an
Android device with Chrome; the app should open without an address bar.
