## Why this matters

Four public machine surfaces are re-generated by PHP on every fetch even though
they change rarely: `/sitemap.xml`, `/manifest.webmanifest`, `/robots.txt`, and
`/.well-known/assetlinks.json`. The live production headers on 2026-11-14 were
`cache-control: no-cache, private` for all of them; the sitemap also carries no
validator. They are small, but crawlers and browsers re-request them for no
reason. The versioned APK (`/downloads/fast-english-1.0.0.apk`, 1,144,598 B) has
`ETag`/`Last-Modified` but no `Cache-Control`, so a repeat download always
revalidates. Separately, production still emits `X-Powered-By: PHP/8.4.26`;
hiding the version is a one-line hardening with no runtime cost. This plan is
deliberately limited to cache headers, one nginx location, and `expose_php`; it
does not change the `no-store` policy for private or HTML pages.

## Steps

### Step 1: Add public cache headers to the sitemap

Change `SitemapController::index()`’s final return to:

```php
return response($xml, 200, [
    'Content-Type' => 'application/xml; charset=utf-8',
    'Cache-Control' => 'public, max-age=3600',
]);
```

A one-hour freshness window matches the sample/`lastmod` cadence; crawlers do
not need a per-second sitemap. Do not add `immutable`: the URL is stable and the
content can change when a sample is published.

**Verify**: `grep -n "max-age=3600" app/Http/Controllers/SitemapController.php`
prints one line.

### Step 2: Add the same header to the three PWA surfaces

In `PwaController::manifest()`, `assetlinks()`, and `robots()`, extend the
existing header arrays:

```php
// manifest
return response()->json([...], 200, [
    'Content-Type' => 'application/manifest+json',
    'Cache-Control' => 'public, max-age=3600',
]);

// assetlinks
return response()->json($statements, 200, [
    'Content-Type' => 'application/json',
    'Cache-Control' => 'public, max-age=3600',
]);

// robots
return response($body, 200, [
    'Content-Type' => 'text/plain; charset=utf-8',
    'Cache-Control' => 'public, max-age=3600',
]);
```

Do not touch `serviceWorker()` (`no-store`) or `offline()` (SW-cached). If a
proxy/CDN is added later, `s-maxage` can be layered on these responses; keep the
browser `max-age` as written for now.

**Verify**: `grep -n "public, max-age=3600" app/Http/Controllers/PwaController.php`
prints three lines.

### Step 3: Give versioned APK downloads an immutable cache

Insert this location in `docker/nginx.conf` **before** the static regex
(`location ~* \.(?:css|js|...)$`, line 122), for example immediately after the
`/build/` block:

```nginx
        # Versioned Android builds (/downloads/fast-english-<version>.apk):
        # the filename changes per release, so the bytes are immutable.
        location ^~ /downloads/ {
            try_files $uri =404;
            add_header Cache-Control "public, max-age=31536000, immutable";
            add_header X-Content-Type-Options "nosniff" always;
            access_log off;
        }
```

Do not apply this to a directory of unversioned files. The current release file
is `public/downloads/fast-english-1.0.0.apk`; the release process must keep
using a new filename for a new build (it already does).

**Verify**:
`grep -n "location ^~ /downloads/" docker/nginx.conf` prints one line, and
`nginx -t` (when available) reports a valid config.

### Step 4: Hide the PHP version

Add one line to `docker/php-production.ini` (near the error settings):

```ini
; Do not advertise the exact PHP patch in every response.
expose_php=0
```

`expose_php` is `PHP_INI_SYSTEM`; a runtime `.htaccess`-style change is not
appropriate here. Rebuild the image to bake it; the kill switch is simply
reverting the line and rebuilding.

**Verify** (static): `grep -n "expose_php" docker/php-production.ini` prints
`expose_php=0`. After a rebuild and deploy:
`curl -sI https://fastenglishpodcast.ir/ | grep -i x-powered-by` prints
nothing. Before a rebuild, the live header still exists; record `NOT EXECUTED`.

### Step 5: Add header regression tests

Append one test to `tests/Feature/S8HeadersTest.php`:

```php
test('public machine surfaces are publicly cacheable', function () {
    foreach ([
        '/sitemap.xml',
        '/manifest.webmanifest',
        '/robots.txt',
        '/.well-known/assetlinks.json',
    ] as $path) {
        $this->get($path)->assertOk()->assertHeader('Cache-Control', 'public, max-age=3600');
    }
});
```

Keep every existing test in the file unchanged. The private no-store assertions
must still pass: those responses are HTML/Inertia, not the four machine
surfaces above.

**Verify**: Pest lane → `S8HeadersTest` and `S2PwaTest` pass.

## STOP conditions

Stop and report if:

- A test or middleware unexpectedly sets `Cache-Control` on these paths after
  your change (for example a global header middleware), or the live/prod header
  is not the exact string.
- The APK release process can overwrite a file without changing its name; the
  `immutable` header would then pin a stale build. Confirm the versioned-name
  assumption before landing.
- A CDN/proxy is already configured outside the container and the operator
  wants `s-maxage` instead; do not add both silently.
- `expose_php` is already set elsewhere in the image to `1`; report the
  conflicting ini before changing it.
- A step's verification fails twice after a reasonable fix attempt.

## Maintenance notes

- If the sitemap becomes large or is served through a CDN, move to `s-maxage`
  and a longer browser TTL; one hour is the current safe default.
- The APK cache rule depends on unique filenames per release. If a build is ever
  replaced in place, reduce `max-age` or append a content hash.
- `expose_php=0` only hides the version; it is not a substitute for patching.
- Reviewer should confirm no private path gained a public cache header: only
  these four machine surfaces and `/downloads/` are in scope.
