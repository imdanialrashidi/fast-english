## Why this matters

- **CI has no pnpm/Playwright cache:** Every PR's 7 shards each cold `pnpm install --frozen-lockfile` (~2–3 min) + `npx playwright install chromium` (~1 min) → ~20 min aggregate GH minutes and slower feedback. `setup-node` supports `cache: pnpm` but it is not wired.
- **No pre-commit hook:** `package.json` has no `husky`/`lint-staged` and `.git/hooks/pre-commit.sample` is disabled. `biome check`/`tsc` failures slip to CI `static` lane (5–15 min per PR) instead of instant local feedback.
- **No `.editorconfig`:** `biome.json` enforces `indentWidth 2 / lineWidth 100 / lf / utf-8` but a fresh editor without Biome extension inserts tabs/120-char lines → noisy diffs.

All three are hours-effort, zero-risk DX wins.

## Steps

### Step 1: Add `.editorconfig`

Create `.editorconfig`:

```
root = true

[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 2
max_line_length = 100

[*.{md,mdx}]
trim_trailing_whitespace = false

[Makefile]
indent_style = tab
```

Mirror `biome.json` values exactly. No other sections.

**Verify**: `cat .editorconfig` exists; `pnpm check` still passes (editorconfig does not affect Biome).

### Step 2: Add pre-commit hook (husky + lint-staged — smallest viable)

1. Install devDeps:
   ```bash
   pnpm add -D husky lint-staged
   ```
   This will update `package.json` + `pnpm-lock.yaml`. Keep `minimumReleaseAgeExclude` handling (repo keeps it in `package.json` `pnpm` field — no `pnpm-workspace.yaml`).

2. Initialize husky (v9+):
   ```bash
   npx husky init
   ```
   This creates `.husky/pre-commit`. Replace its body with:
   ```sh
   # Fast English Podcast — local gate; mirrors CI static lane's cheapest checks.
   # Runs only on staged files; never on server/pb_hooks (biome excludes those by design).
   npx lint-staged
   ```
3. Add to `package.json` `lint-staged` config (top-level `lint-staged` key or `package.json` field):
   ```json
   "lint-staged": {
     "*.{ts,tsx,js,mjs,cjs,json}": "biome check --write --no-errors-on-unmatched --staged-files",
     "*.{ts,tsx}": "tsc --noEmit --pretty false"
   }
   ```
   Prefer the JSON key approach if `biome check --staged-files` is supported in installed Biome 2.5.6; if not, use a shell snippet: `biome check --write` over staged `*.ts` via lint-staged default. Verify `npx biome check --help | grep staged` first; if `--staged-files` not supported, use `biome check` with lint-staged's file list passing (`biome check --write` will be invoked per file by lint-staged). Document which you chose.

4. Note: `biome.json` excludes `server/pb_hooks` — the hook respects that. Do NOT add `server/pb_hooks` to lint-staged.

5. If `pnpm verify:fast` via `tsc --noEmit` on staged `*.ts` is too slow (20s), reduce to `biome check` only and keep `tsc` as CI-only — either is acceptable; note in `CONTRIBUTING.md`.

6. Ensure `.husky/pre-commit` is executable (`chmod +x .husky/pre-commit` is done by husky).

**Verify**: stage a dirty file (create `tmp_test_precommit.ts` with `const x=1` mismatched style, `git add` it, run `bash .husky/pre-commit` or `npx lint-staged` — it should auto-fix and exit 0; then `git restore --staged tmp_test_precommit.ts; rm tmp_test_precommit.ts`). `pnpm verify:fast` still green.

### Step 3: Wire CI cache for pnpm + Playwright

Edit `.github/workflows/quality.yml`:

- In each job (`static`, `backend`, `e2e`) where `actions/setup-node@v7` is used with `node-version: 24`, add:
  ```yaml
  - uses: actions/setup-node@v7
    with:
      node-version: 24
      cache: 'pnpm'
      cache-dependency-path: pnpm-lock.yaml
  ```
  This caches `~/.pnpm-store` keyed by `pnpm-lock.yaml` hash.

- For Playwright browsers, add after `ci-install` or as a parallel cache:
  ```yaml
  - uses: actions/cache@v4
    with:
      path: ~/.cache/ms-playwright
      key: ${{ runner.os }}-playwright-${{ hashFiles('pnpm-lock.yaml') }}-1.62.0
      restore-keys: |
        ${{ runner.os }}-playwright-
  ```
  Place it before `Install dependencies` so `ci-install.sh` hits cache. `scripts/ci-install.sh` runs `npx playwright install chromium --with-deps` or `playwright install chromium` — the cache must precede it. If `ci-install.sh` already does `playwright install`, the cache will short-circuit download (Playwright checks cache existence).

- Do not change `scripts/ci-install.sh` logic unless required for cache key (e.g. adding `--with-deps` only in CI). Prefer workflow-level cache.

Apply to all 3 lanes; `e2e` has a 5-shard matrix — the cache step is per-shard (actions/cache restores per runner; that's fine).

**Verify** (local, no GH run needed): `cat .github/workflows/quality.yml` shows `cache: 'pnpm'` in each setup-node; `grep -n "actions/cache" .github/workflows/quality.yml` hits; `pnpm verify:fast` still green locally. Do not run GH workflows locally.
