  out of scope — the plan's premise ("already has the eviction branch") was

  `__fepAdminRate` window, same per-bucket composite keys, same budgets);
  the caller-facing `{status, code, message}` shape is kept.

  progress record stays legal (200). Verified during execution that PB 0.39
  rejects 0 on ANY save of a required number field (create AND update), so
  the final contract rejects 0 on both paths with 400 `invalid_position`;
  on update, a stale revision (409) is reported before the 0 rejection. The
  client (`useProgressSave`) drops non-409 errors silently, so the 400 is
  inert in the current UI. Smoke scenarios assert the final contract.
- **Plan 005, smoke**: the S0 per-threshold loop additionally asserts
  `kind === 'level_selection_required'` (reviewer hardening).
