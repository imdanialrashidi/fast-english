## Findings considered and rejected (2026-11-14 audit)

These were measured and deliberately not planned; do not re-audit them silently.

- **Responsive cover thumbnails (800×450 → 400×225):** current covers are
  26–32 KB JPEGs, already lazy-loaded, HTTP-cached one year, and only six
  visible thumbnails are 44–104 px. The byte saving is real but needs a
  derivative-generation + cleanup pipeline and payload changes across
  `TopicCard`/Today/Saved/AudioConsole; it is not worth the storage/backfill risk
  until the catalog is much larger or field image bytes become visible. Revisit
  at 100+ published topics.
- **SMS send queue:** `PhoneVerificationCodes::issue()` calls the provider
  synchronously (`config/sms.php` timeout 8 s), so a slow MelliPayamak response
  can hold the login-code request. Queueing removes the immediate “send failed”
  feedback the verify screen currently promises; it is a product/UX decision,
  not a safe quick win. Keep `MELIPAYAMAK_TIMEOUT` bounded in the meantime.
- **OPcache / realpath cache:** measured on 2026-11-14 after `/`, `/login`,
  `/faq`, and `/admin/login`: 1,462 cached scripts, 39.7 MB used of 128 MB, no
  OOM or hash restarts. `opcache.max_accelerated_files=10000` is not a
  bottleneck for this workload; do not raise it without a new measurement.
- **Brotli:** the runtime nginx image has `http_v2_module` but no brotli
  module (`nginx -V`). gzip level 6 is the available path; adding a module to
  save ~10–15% on already-small assets is not justified now.
- **Filament theme (683,714 B raw / 68,860 B gzip) and staff `app.css`
  (82,495 B / 15,159 B gzip):** admin/staff-only surfaces, never loaded by the
  learner/public bundle. Revisit only if the panel feels slow; measure admin
  render first.
- **Account page payment queries:** `AccountController` issues open + latest +
  history (10-row limit). Bounded and bounded again by history; combining them
  would couple unrelated states for ~0.4 ms. Not worth it.
- **`due_words` dedupe:** Today counts due words in the shared Inertia prop and
  again in `DailyPlan`; one query. Coupling `HandleInertiaRequests` to the
  planner costs more than the query saves. Leave it.
- **Favicon (30 KB ICO) and OG image (164 KB 16-bit PNG):** the favicon is
  cached and versioned by mtime; the OG image is crawler-only. No user-facing
  LCP path.
- **`app.css` split for three staff 2FA pages:** the learner bundle does not
  load it; splitting it is cleanup, not performance, for the public product.

The older 2026-10-18 rejections above (placement publish race, synchronous
backup, response-hardening headers, lucide barrel, CI composer cache, etc.)
remain recorded in the plan-006-era history and are not re-litigated here.
